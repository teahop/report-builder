Report Builder — one-page brief

A drafting service for school-psychology evaluation reports. Typed source documents go in; a clinician-reviewable section comes out, with every claim traced to evidence. The clinician signs; the tool drafts and never decides.

home · operator console · voice memory · repo

Problem

Writing these reports is slow, and a fluent model paragraph is dangerous if it cannot show where a fact came from. The interesting part is not “AI writes the report.” It is a pipeline that extracts a structured fact ledger, checks it deterministically, drafts prose without leaking internal ids, and fails loudly when validation does not hold.

Architecture

Not an agent graph and not a vector RAG store. Stages talk over FastAPI; the ledger is the memory of the case for one request (nothing is persisted on the server).

  • POST /ingest — classify a document; the operator must confirm (never silent).
  • POST /extract — one model call per new narrative source → ledger + gap list.
  • POST /conflicts — no model; record conflicts vs perspectival variance.
  • POST /draft/history and /draft/referral — draft from confirmed context; code aligns spans to facts; a voice gate scores the prose against compiled clinician rules.
  • Langfuse traces model calls when keys are set. Case data is synthetic on this host.

Stack

FastAPI · OpenAI (confirm_synthetic: true required) · Langfuse · voice_store.json (compiled Class A rules) · pytest + smoke traces · Render. No LangGraph, no ADK, no embedding index. Production drafting for real cases is a separate BastionGPT path, not this URL.

Evals (TRACE)

A 20-run History baseline failed 20/20 by opening with date of birth / age — a header fact the model had been told was important. The shipped fix rewrote that rule (age belongs in the header, not the History opener). After-set: opener 0/20 → 20/20; a summarative-phrase tripwire still fires 1/20. Focused referral checks pass on synthetic smoke. Extraction quality is not accepted; demos use a cached synthetic ledger. Test baseline at repo extraction: 147/150 with three known failures (do not wipe human review rows to go green).

Memory (voice gate, not a chatbot log)

  • Keep: Class A only — eight rules Molly stated (A1–A8). Positive voice lives in few-shot examples, not this store.
  • Write: recompiled from the ruling ledger at session close, behind propose → approve → apply. This URL has no write endpoint.
  • Lives: voice_store.json, version-controlled next to the code. The ruling ledger stays local by design.
  • Retrieve: evaluate_voice_gates loads the file from disk at review. The recall request does not contain the rule text. Proof: /memory (score a temptation; refresh; same store).
  • Forget: never a delete. The ledger is append-only; the store compiles the live, non-superseded set. Retraction is a new entry. A4/A5 stay inert without a case ledger — different from forgotten.
